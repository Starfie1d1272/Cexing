# 原生流量账本

## 口径与上游依据

上传、下载是当前内核跟踪的数据字节，合计为两者之和；不是系统网卡总量、运营商计费量或订阅套餐余额。总量日/月账本不采集应用、域名、连接明细；来源账本单独保存 UID 用量及有界访问线索，均为本机私有数据。

固定内核 [Mihomo statistic manager](https://github.com/vernesong/mihomo/blob/daf3ad03021cca6031f4a7303ca6d861a14d5a16/tunnel/statistic/manager.go) 的 `Total()` / `Snapshot()` 为进程累计，`Now()` 为一秒速率；连接关闭不会扣除累计。当前固定模块图没有 `ResetStatistic()` 调用，但客户端仍防御计数回退。参考 [v2rayN StatisticsManager](https://github.com/2dust/v2rayN/blob/master/v2rayN/ServiceLib/Manager/StatisticsManager.cs) 将日累计、总累计与存储分离的思路，本实现另加会话检查点和缺失区间处理；不把 Web 面板短时曲线当作跨重启账本。首页、详情的实时速率沿用 `/traffic`；账本只用 `/connections` 的 `uploadTotal/downloadTotal`，不积分速率。

“本次”是扩展核实的 VPN 会话；断开后保留最后一次值，新会话首样本建立基线；确认会话身份变化后、累计读取成功前，本次显示未知，日/月历史保持原值，未知本次状态单独持久化，首样本失败后断开或进程恢复也不回显旧会话。Go runtime 可在重连时继续存在，因此首样本总量不能全算成本次。首次启用之前不恢复历史；今日/本月只含启用后有证据的增量。单位沿用内核页面的 1024 进位 B/KB/MB/GB/TB。

## 采集与恢复

`AppRuntime` 既有五秒健康检查在核实会话后触发一个 single-flight 累计采样，连接成功时立即触发首样本。页面不拥有采集器；Ability 销毁不释放 VPN/采集。`LiveViewKeeper` 复用最近采样差分速率，删除原六十秒 REST 轮询。未取得长时任务、系统取消/挂起后台执行或用户关闭保活时，不能保证五秒调度；同一会话下后续累计样本仍能追回总差额，但不保证每日的完整分配。

会话身份由 VPN Extension IPC 核实，采样开始和完成都核对身份；断开使在途回调失效。热重载不改变会话身份，正常累加；内核进程退出后新扩展会话建立新基线。同会话恢复接续持久检查点，不靠“新值大于旧值”猜测进程连续性。若计数回退，两个方向都重新基线，保留已记字节并标缺失，不把回退后的计数加作历史。

初始基线之前和断开前未采到的尾段不具备精确分配证据，本次与相应日/月标“部分记录”。暂时请求失败本身不会丢弃基线；同身份再次采到累计值能恢复中间增量。首次启用的日/月有启用前缺失，始终标部分。

## 日/月与时间变化

按设备本地日历键分桶。同日同月且时间前进、时区偏移不变的差额正常计入。样本跨午夜时，差额能计入本次；如果仍在同月，也能计入本月，但不能确定它属于哪一天，故不分摊到日桶，并标两端日桶缺失。跨月相同处理。时钟回退或时区偏移变化时，差额只进入本次，日/月不造数，两端标缺失。前跳未跨日/月时整段仍属于同一桶。

曲线只保留内存中最近五分钟、至多六十个采样点，显示实际观测间隔的平均速率，与实时 `/traffic` 数值可能不同；超过十五秒的区间断线，进程恢复不补曲线。

## 持久化与故障边界

应用私有 Preferences 独立存储一个版本化 JSON，同时保存累计和原始检查点。保留最近访问的三十五个日桶和十四个月桶；数据最大三十二 KB，不包含连接元数据。单 writer 与一个可替换 pending 快照，慢盘不会积压无限任务。异步 `flush` 不被 VPN 启停等待；存储失败只提示“记录未保存”，不阻止连接。

进程异常退出可能发生在最近检查点落盘前；同一核实会话可用下次累计差额补回，若内核一同退出则无法恢复尾段，保留已保存值并标部分。初始化读存储失败可在前台/上下文重绑重试，读取成功前不采样以免覆盖旧历史；结构损坏（包括缺少检查点对应日/月桶）或不支持版本时保留原文件，当前进程只显示未保存的新记录，不覆盖原历史。不得把部分记录称为全天准确统计。支持文件中的固定源码/产物身份仍按构建、主机模拟和真机证据分别记录。

## 界面约束

首页不增加卡片，通过现有速率区的箭头打开流量页，未连接时同一区域也能打开已保存统计。详情只显示上传/下载实时速率、短曲线、本次/今日/本月上传下载及合计；实际缺失标“部分记录”，写失败标“记录未保存”。口径说明仅在工程文档，不在页面放常驻解释或套餐暗示。

## 来源采集与身份

应用计量独立于上述日/月账本，范围仅为本机系统 TUN 进入内核、已建立 statistic tracker 的客户端字节。排除 VPN 的应用不可观测；DNS 劫持、建连失败等没有 tracker 的路径不造数，节点封装与机场账单也不在此口径。旧 `/connections` 和日/月采样不变，应用明细不追溯补分历史。

固定内核补丁覆盖 TCP 普通/buffer/unwrap 读写、UDP 读写及创建时的初始 `peekLen`。只给 `pushToManager` 路径创建观察句柄，避免嵌套 tracker 重复；通过现有 TUN metadata addition 携带不序列化的会话上下文，旧 TUN 的迟到 tracker 也不进入新会话；句柄属于原 TUN 会话，Close 幂等且只减少活跃连接数，关闭后的并发迟到增量仍记同一行，不再累计终值。TUN UDP 在 NAT 查找前逐包查询身份；共享 UDP worker 只投递到至多 128 个异步槽，饱和时丢包。NAT key 在既有 listener 身份之外加入会话、UID、原始四元组和来源出口的摘要，避免源端口被另一 UID 复用时沿用旧出口；未知 UID 使用独立分区，不借用已知 UID 缓存。原始地址元数据独立保留。此路径的高吞吐和持续负载表现须独立验收。出站首个实际 adapter 类型区分代理、内核 DIRECT 与未分类，不依赖策略名。应用身份未知与路由未分类互不替代。

TCP 建立出站前和每个 UDP 包进入 NAT 前从 `RawSrcAddr/RawDstAddr` 取得原始地址和非零端口，不能使用 Fake-IP 还原后的目的地址。Go 请求队列至多 256 条，通过同一认证 Controller 的单个 `/ohos/app-traffic/identity` 消费者事件唤醒并连续排空，每批至多 32 条、已发送待回复至多 128 条；较早截止的请求先发送，回复或超时释放容量后立即唤醒后续批次，空闲 WS 每秒发送心跳；首包查询等待上限 1.2 秒，在连接 goroutine 上等待，不阻塞 NAPI worker 或主线程。Tracker 继承本次查询结果；未经过前置查询的兼容计量路径仍采用 8 秒过期的异步归因。VPN Extension 生命周期持有消费者，API 23+ 仅调用 `connection.getConnectOwnerUid`；API 22 记 unsupported。原生 WebSocket 在 API 26 启用 `supportOriginPort`，保留 Controller 的 `9090` 来源端口，并对回环连接禁用系统代理；服务端继续校验完整同源地址。API 23–25 使用带相同认证的 `GET /ohos/app-traffic/identity?transport=poll` 长轮询，最多等待一秒，有请求即返回；单个在途请求可取消，响应后立即续取，禁用系统代理和 HTTP 缓存。WS 与轮询共用单读者互斥及队列；成功轮询响应提供 2.4 秒消费者短租约，使两次请求之间仍可入队，查询自身仍受 1.2 秒期限约束；停止会话清除租约。传输分支已可在本机验证，各 API 的系统 UID 查询成功率仍需设备验收。UID 不等于已验证的应用身份，共享 UID 也可能存在。三方跨 UID 包名/资源查询需要系统级权限，当前没有已验证的普通消费者 VPN 公开替代路线，故不调用包名/图标 API、不声明系统权限，也不猜测应用。官方 UDP 查询可能在远端无匹配时按本地地址匹配，不能解释为严格四元组证据；无 UID 时不自行猜测。平台至多 128 个在途查询，1 秒超时，超时后的底层 Promise 仍占槽直到实际完成，停止/重启也不会绕过上限。查询完成即进入有界回复队列，在下一个事件循环合并至多 32 条并由单个 HTTP 发送者连续排空，批次之间不增加固定等待；停止后旧发送请求仍持有发送槽直至完成，迟到查询不能进入新会话。单个慢查询不会拖住同批已完成查询。

身份批量 POST 带会话 ID 与请求 ID。未知先计数，成功回复在同一聚合锁内移动已累计字节、连接数和活跃数，随后增量直接归已识别行；重复、超时或旧会话回复不再移动。失败原因只保留有界类别计数。最多 128 个已知 UID，超限继续计入未知。首包查询未取得身份且没有来源规则时沿用原分流；存在任意来源强制规则时，未知身份的新 TCP 连接或 UDP 包被拒绝并计入 `routeIdentityRequired`，避免错误绕过来源规则。

`GET /ohos/app-traffic` 与 `CoreApi.getAppTraffic()` 返回 schemaVersion 1：`session/state/startedAt/endedAt/partial/totals/apps/identityFailures/routeTargets`；时间是 Unix 毫秒。每行含 `identityStatus/uid/bundleName/bundleVerified/routes/recent/routeTarget/lastSeen`，routes 的 `proxy/direct/unclassified` 分别含 `upload/download/connections/active`。未知行 `identityStatus=unknown、uid=-1`，官方查询成功行仅为 `identityStatus=uid`。所有行 `bundleName` 为空、`bundleVerified=false`，不得据 UID 展示已识别应用。每行内存保留最近四条访问目标、规则类型及至多八段策略链；目标优先域名，否则保留原始目标 IP，不含完整 URL、规则 payload 或端口，不写日志或导出支持包。

来源列表按 UID 自动持续归集，使用持久稳定编号并按所选时段的代理用量排序；持续展示近期访问目标与流量，帮助用户判断来源，支持持久备注及跨重连保留的出口设置。备注由用户填写，不代表系统验证的应用身份；真实名称、图标和系统 VPN 包名排除已依据权限研究排除在当前来源方案的交付前提之外，见 [ADR 0005](../decisions/0005-uid-source-identity.md)。UID 仅在技术详情显示。

## 持久来源出口

`PUT /ohos/app-traffic/route` 接收 `{session,uid,target}`。首次设置要求当前会话已观测该 UID；已有持久规则允许在尚无本次流量时修改或删除。空 target 恢复跟随分流并删除持久规则，`DIRECT` 或当前策略组选择相应出口。服务端验证会话、UID 与出口存在性，成功返回 204。

内核私有目录中的 `uid-routes-v1.json` 保存版本 1 规则，最多 2048 个 UID、单出口名称至多 256 UTF-8 字节、文件至多 3 MiB。保存使用同目录临时文件、文件同步、原子替换及目录同步；确认持久化后才发布内存策略。替换前失败保留原文件与生效规则；替换后目录同步失败标记 `writeError/blocked`，暂停新连接并要求重读确认磁盘状态。断开不清除规则，内核初始化读取文件，TUN 开始转发前装载规则，使首个 TCP/UDP 请求使用已保存出口。

`GET /ohos/app-routes` 独立返回 `{schemaVersion,session,state,storage,blocked,rules,routeTargets}`，每条规则含 `{uid,target,available}`。规则文件损坏或读取失败时保留原文件、显示异常，控制通道可用，新连接被阻止。`POST /ohos/app-routes/recover` 接收当前 `{session,action}`：`retry` 重读文件；`reset` 先在私有目录备份原始文件，再原子清空规则。界面仅在用户确认后执行重置。保存、重读和重置均绑定当前会话，旧会话请求不能更改新会话策略。

来源规则先于规则/全局/直连模式选择出口；修改只影响新建 TCP 连接；UDP 后续包按新出口重新选择 NAT 映射，可能打断正在进行的 UDP 会话。配置热重载删除所选出口时保留原规则，标记出口不可用，该来源新连接失败；用户可以更换出口或恢复跟随分流。直连仍经过 TUN 计量。系统 TUN 的 TCP/UDP 53 劫持由共享 resolver 处理，不经过来源出口钩子；DNS 沿用统一解析。界面分别展示保存反馈与带时间的实际出口记录，保存成功不代表真实转发已验收。

`SourceTrafficStats` 独立采样规则状态，在采样前后核对扩展与 Controller 身份。规则与流量摘要的读取失败互不覆盖。Preferences 的独立 `routes` 项缓存最近确认的规则，与来源账本共用单 writer；断开或重启后可只读查看，缓存不参与执行或恢复策略。文件损坏、读取失败及阻塞写入状态保留旧缓存供核对。管理列表独立于流量时段和来源历史；无本次流量的已存规则仍可管理。出口状态以当前规则接口为准，历史访问记录仅作流量证据。


Go 汇总保存当前内核会话计数与有界 recent。正常停止写内存状态 `closed`，仍有活跃 tracker 时标 partial；Controller 不可达时 `getAppTraffic()` 返回 null。Go 新会话从零计数，宿主将这些快照纳入下述持久来源账本。现有日/月总量账本的采样与持久化保持独立。

## 持久来源历史

`SourceTrafficStats` 由 `AppRuntime` 初始化、在连接后立即采样并跟随既有五秒健康调度；页面打开与关闭不拥有采集。私有 Preferences `cexing_source_traffic_v1` 保存版本化 JSON，包含累计来源用量、35 个日桶、14 个月桶、来源编号/用户备注与采样检查点。流量页提供本次、今日、本月、累计选择，断开或进程重启仍能查看已保存的数据。来源备注在输入时提交给单 writer，失败显示“记录未保存”。

来源索引使用数字 UID：普通重启和 VPN 重连沿用相同索引、编号与备注。它表示系统 UID 来源，不声明为某一应用的永久安装身份；共享 UID 的流量合并记录，卸载重装或系统重分配 UID 后，用户应结合访问目标调整备注。未知来源独立聚合，不接受应用备注。每个来源只保存最近四条域名/IP、规则类型和出口线索，不保存完整 URL、端口、原始包或配置；这些记录不进入日志和诊断导出。

采样前后核对扩展会话与 Controller 身份，接受运行中同一来源会话的累计快照。来源计数在每个会话从零开始，因此首次快照纳入已产生的字节；后续仅按检查点差额入账。同会话重读和进程恢复不重复累计；未知字节后续归到 UID 时，允许从未知来源扣除并转入对应来源，保持总量守恒。计数回退或容量异常拒绝推进检查点并标缺失。首次设置出口须在当前会话观测该 UID；已有持久出口规则的管理独立于历史流量。

日/月分配沿用观测时间边界：跨日、跨月、时区或时钟变化时，不把无法定位的差额编造到某一天；跨期间的未知→UID 更正也可能无法定位历史归属，相应时段标“部分记录”，累计来源仍按完整快照修正。断开与进程异常退出前的未采样尾段不能承诺恢复；同一仍存活会话可用后续快照追回差额。后台调度可用性仍受系统运行条件约束。

最多保留 2048 个已知 UID 及未知来源；序列化上限为 2 Mi UTF-16 字符，按 UTF-8 保守估算不超过 6 MiB，低于 Preferences 单值上限。达到容量边界时保留既有历史与检查点，显示记录未保存/部分记录，不静默删除来源。单 writer 加一个可替换的最新待写快照，避免慢存储积压；损坏或不支持版本的文件保留且不覆盖，读取暂时失败可在前台重绑时重试。已有总量历史无法反推出之前的各来源用量，来源历史从该能力首次成功采样开始。
