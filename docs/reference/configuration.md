# 配置导入与覆写契约

## 实现与目标

现有 `ProfileStore` 支持 URL、`.yaml/.yml` 文件、剪贴板、私有存储、来源更新和激活元数据；下载响应显式读取字符串，自动命名不从 URL 令牌生成。原生内核设置是少量运行参数覆写，**不是 Merge YAML 或脚本兼容实现**。

激活、编辑、手动及自动更新共用配置门禁。Go worker 将原文、每订阅启用的 Merge 和平台投影编译为不可变版本；离线时完成 Mihomo 全量解析，运行中先检查 YAML/引用及本机 provider 缓存，热加载入口在应用前完成 Mihomo 解析。确认热加载成功后才原子发布 `profile-versions/state.json`，其中保存当前、前一有效版本和每订阅版本索引；启动从该指针读取生成配置。缺少 provider 缓存或 GeoSite 等资源时明确拒绝，不下载私人 provider。导入仍允许保存原文供后续处理。明确拒绝保留有效指针；请求超时或控制面不可达时结果未知，持久标记并阻止后续更改。生成版本与原文保存在应用私有目录，不写入日志。云端构建不能证明真机转发健康。

| 格式 | 接入方式与边界 |
|---|---|
| 完整 Mihomo YAML / 订阅 YAML | 保留普通导入；完整解析、provider/引用校验由新流水线承担 |
| Merge YAML | 已固定 [Clash Verge v2.5.8 语义](config-compatibility/spec.md)；编辑页可保存每订阅草稿、预览固定 section 差异，并显式应用或清空停用；启用的 Merge 随订阅更新重新编译，草稿修改不改变已发布版本 |
| 可移植策略预设 | 待实现独立、可验证的策略转换，不塞入 UI 或存储模块 |
| Clash Verge `Script.js` | 可导入在原平台生成的最终 YAML；任意 JS 执行需另行设计受限环境 |
| OpenClash Shell/Ruby | 可导入最终 YAML 或移植策略语义；不在手机直接执行 shell/Ruby |

## 手机网络访问范围

局域网代理首次安装默认关闭。旧版本的 `allowLan=true` 没有主动授权记录，升级后按关闭读取；用户须重新确认共享风险。覆写页确认开启或关闭后立即保存授权设置，下次启动 VPN 生效。关闭保存失败时明确保留“原授权仍可能有效”的提示与开关，用户须再次关闭重试；只有撤销成功落盘才报告保存成功，当前会话不会自动停止共享。其他设置保存不授予局域网代理权限；订阅与 Merge 不能覆写宿主 LAN 默认。

宿主 LAN 授权仅开放设置中的 mixed 代理端口。mixed 绑定地址由宿主强制与授权匹配，订阅 `bind-address` 不生效。普通 `listeners` 独立监听地址统一回环；订阅声明的其他顶层代理端口、独立服务端与 `tunnels` 停用。这是手机 VPN 的兼容边界：不支持订阅要求的独立 LAN 服务端口或 tunnels 转发服务，不保证此类网关/服务端配置完整兼容；原文保留，但这些监听设置不会生效。系统 fd TUN 仍由宿主单独创建。已认证 REST 重载继承本次原生启动的 LAN 与 mixed 端口，请求不得更改这两项；新的设置须经原生确认并重新启动 VPN。

DNS 独立监听固定为 `127.0.0.1:1053`，订阅与 Merge 的 `dns.listen` 不生效，开启 LAN 代理也不开放 LAN DNS。系统 TUN 的 DNS 劫持继续经内核内部解析器处理 TCP/UDP，无需拨号到独立 DNS 监听端口。升级不会自动重启已运行会话，生效及同网不可达仍需真机核验。

## 有效配置事务

原始配置 → 可选 Merge → 平台强约束 → 候选校验 → 暂存不可变版本 → 热重载（若运行中）→ 原子发布状态指针 → 启动读取或保持运行。

- 原始订阅、覆写与生成配置分别保存；保留来源元数据及上一份有效版本。
- 激活、订阅更新、配置切换和编辑均经同一事务；旧 `profiles/*.yaml` 仍为导入兼容路径，有效版本从状态指针读取。
- Controller 强制回环、共享端口、应用生成的 secret、external-ui 和系统 TUN 参数不得由订阅或覆写修改。
- 校验 `proxies`/`proxy-providers`、策略组引用、规则目标、必要节点及资源。占位 URL 或缺失 provider 不当作可运行配置。
- 生成或应用失败保留上一份有效配置，内核运行失败也应回滚；不能仅做到文件原子替换。
- 预览和错误不泄漏凭据，日志不记录完整配置、订阅 URL 或密钥。

## 交互与可移植策略

普通入口为 URL/文件/剪贴板；高级入口选择策略或导入 Merge。用户完成“添加订阅 → 选择策略 → 校验 → 启用”，以后更新重新应用覆写，不要求手改大量 YAML。

跨平台兼容以策略语义为准：区域组、服务组依赖、规则优先级、必要节点及幂等性。`smart`、`url-test` 与 LightGBM 启用状态分别表达，不静默改变选点行为。网关 NAS/设备规则与桌面 DNS 不自动继承到手机。

个人 Canonical v3 策略作为外部私有输入；公开代码只定义通用接口和合成测试。精确行为须用获授权的策略或脱敏夹具验证，历史 Android 模板不能自动成为权威策略。

### Smart 地区策略

首次导入中，若原文与启用的 Merge 均无 `smart`、`url-test`、`load-balance` 策略组，且所选 `select` 组含直接列出的节点或已校验的 provider 节点，可预览按名称猜测的地区、未知节点和数量。用户可以逐个修正猜测；猜测并不证明节点的实际地理位置。`use` 与 `include-all` 只读取应用私有目录中已校验的 provider 快照，不请求远端 URL；快照缺失时显示待解析，不把尚未加载的节点当作空集。`filter` 与 `exclude-filter` 仅筛 provider 节点，直接列出的节点先行分类。嵌套策略组、relay、dialer 引用不会被展开为普通节点。

“按地区”只生成有节点的 Smart 组与一个新地区入口；“全部节点”要求至少两个已验证节点。新入口加入用户指定的原 Selector 作为一个选项，新入口只指向生成的 Smart 组，不回指原 Selector。原规则的顺序、条件和目标均不变。生成的 Smart 组设置 `empty-fallback: REJECT`，避免动态空组落到直连。“仅创建”保留当前手动选项；“创建并启用”记录用户明确的选取意图，在 Controller 就绪后只选择一次新增入口，之后的手动选择不被订阅更新覆盖。关闭时移除生成入口并尝试恢复启用前的选项；若原选项已失效则先要求用户手动选取可用节点。策略计划保存在该订阅的不可变版本来源记录中；关闭、重新启用及订阅更新都经同一配置事务重新生成并校验，原订阅文本保持不变。

## 验收

覆盖完整 YAML 与 provider；保留节点；无重复组/规则、无悬空引用；缺必要节点明确失败；保持规则优先级；重复转换幂等；更新重新应用覆写；启动/重载平台字段一致；生成、保存和内核应用失败均可回退。合成测试与云端构建验证事务结构；真机上仍需核对启动和热重载实际生效、停止确认及网络转发。
