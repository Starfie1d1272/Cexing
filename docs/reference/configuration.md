# 配置导入与覆写契约

## 实现与目标

现有 `ProfileStore` 支持 URL、`.yaml/.yml` 文件、剪贴板、私有存储、来源更新和激活元数据；URL 导入与来源更新统一以 `ClashMeta/1.0 Cexing/<应用版本>` 请求原站的 Clash YAML，版本取自已安装应用信息；下载响应显式读取字符串，自动命名不从 URL 令牌生成。原生内核设置是少量运行参数覆写，**不是 Merge YAML 或脚本兼容实现**。

激活、编辑、手动及自动更新共用配置门禁。Go worker 将原文、启用的全局 Merge、本订阅 Merge 和平台投影编译为不可变版本；离线时完成 Mihomo 全量解析，运行中先检查 YAML/引用及本机 provider 缓存，热加载入口在应用前完成 Mihomo 解析。确认热加载成功后才原子发布 `profile-versions/state.json`，其中原子保存启用的全局 Merge、当前、前一有效版本和每订阅版本索引；启动从该指针读取生成配置。缺少 provider 缓存或 GeoSite 等资源时明确拒绝，不下载私人 provider。导入仍允许保存原文供后续处理。明确拒绝保留有效指针；请求超时或控制面不可达时结果未知，持久标记并阻止后续更改。生成版本与原文保存在应用私有目录，不写入日志。云端构建不能证明真机转发健康。

| 格式 | 接入方式与边界 |
|---|---|
| 完整 Mihomo YAML / 订阅 YAML | 保留普通导入；完整解析、provider/引用校验由新流水线承担 |
| Merge YAML | 已固定 [Clash Verge v2.5.8 语义](config-compatibility/spec.md)；订阅顶层提供全局共同基线，原编辑页保留本订阅例外；两层均可保存草稿、预览固定 section 差异，并显式应用或清空停用。全局先于本订阅，数组整体替换；启用的 Merge 随订阅更新重新编译，草稿修改不改变已发布版本 |
| 可移植策略预设 | [组合分流](routing-intent.md)将规则所有权、候选范围和算法独立保存，沿用共同编译/编辑/发布事务 |
| Clash Verge `Script.js` | 可导入在原平台生成的最终 YAML；任意 JS 执行需另行设计受限环境 |
| OpenClash Shell/Ruby | 可导入最终 YAML 或移植策略语义；不在手机直接执行 shell/Ruby |

新导入先以唯一名称保留本次来源，完成原文临时文件的写入、fsync、关闭及来源/更新身份/元数据，再以最终 YAML 的同步 rename 发布；最后取消检查与 rename 之间不让出执行。提交前取消或失败只清理本次创建的临时文件、侧车及当前元数据中的本次条目，旧来源、孤立资料和其他并发导入保留；清理失败单独提示。提交后页面离开不撤销已保存来源。此约束覆盖可观测的进程内失败，不宣称多文件在进程崩溃时原子提交；崩溃残留占用旧名称，重试选新后缀。导入错误只展示固定类别与合法 HTTP 状态码，日志不包含原异常、URL、正文或路径。

## 手机网络访问范围

局域网代理首次安装默认关闭。旧版本的 `allowLan=true` 没有主动授权记录，升级后按关闭读取；用户须重新确认共享风险。覆写页确认开启或关闭后立即保存授权设置，下次启动 VPN 生效。关闭保存失败时明确保留“原授权仍可能有效”的提示与开关，用户须再次关闭重试；只有撤销成功落盘才报告保存成功，当前会话不会自动停止共享。其他设置保存不授予局域网代理权限；订阅与 Merge 不能覆写宿主 LAN 默认。

宿主 LAN 授权仅开放设置中的 mixed 代理端口。mixed 绑定地址由宿主强制与授权匹配，订阅 `bind-address` 不生效。普通 `listeners` 独立监听地址统一回环；订阅声明的其他顶层代理端口、独立服务端与 `tunnels` 停用。这是手机 VPN 的兼容边界：不支持订阅要求的独立 LAN 服务端口或 tunnels 转发服务，不保证此类网关/服务端配置完整兼容；原文保留，但这些监听设置不会生效。系统 fd TUN 仍由宿主单独创建。已认证 REST 重载继承本次原生启动的 LAN 与 mixed 端口，请求不得更改这两项；新的设置须经原生确认并重新启动 VPN。

DNS 独立监听固定为 `127.0.0.1:1053`，订阅与 Merge 的 `dns.listen` 不生效，开启 LAN 代理也不开放 LAN DNS。系统 TUN 的 DNS 劫持继续经内核内部解析器处理 TCP/UDP，无需拨号到独立 DNS 监听端口。升级不会自动重启已运行会话，生效及同网不可达仍需真机核验。

## 有效配置事务

原始配置 → 可选全局 Merge → 可选本订阅 Merge → 已启用的组合分流 / 旧地区策略和个人编辑 → Smart（保留托管出口算法）→ 宿主参数及平台强约束 → 候选校验 → 暂存不可变版本 → 热重载（若运行中）→ 原子发布状态指针 → 启动读取或保持运行。

- 原始订阅、全局草稿、本订阅覆写与生成配置分别保存；版本来源记录独立的全局快照和本订阅覆写，保留来源元数据及上一份有效版本。既有单订阅覆写不会自动提升为全局。
- 全局默认空且不改变旧行为。应用时先以当前启用订阅和本订阅例外生成、校验及热重载，再与版本指针一起原子发布；失败保留旧全局和旧有效版本。其他订阅在启用或更新时以最新全局重新生成，旧全局缓存不能直接激活；断开后的启动也比较版本全局快照并重新生成。未启用订阅时可保留草稿，预览或应用须先选择完整订阅。
- 全局和本订阅沿用同一固定 Merge 方言：规则、节点、策略组等数组整体替换；不追加、不按名称合并。Smart 自动转换及地区策略在两层 Merge 之后执行，宿主 LAN 同意状态、DNS 回环监听及其他平台安全字段最后生效。
- 激活、订阅更新、配置切换和编辑均经同一事务；旧 `profiles/*.yaml` 仍为导入兼容路径，有效版本从状态指针读取。
- Controller 强制回环、共享端口、应用生成的 secret、external-ui 和系统 TUN 参数不得由订阅或覆写修改。
- 校验 `proxies`/`proxy-providers`、策略组引用、规则目标、必要节点及资源。占位 URL 或缺失 provider 不当作可运行配置。
- 生成或应用失败保留上一份有效配置，内核运行失败也应回滚；不能仅做到文件原子替换。
- 预览和错误不泄漏凭据，日志不记录完整配置、订阅 URL 或密钥。

## 交互与可移植策略

普通入口为 URL/文件/剪贴板；高级入口选择策略或导入 Merge。用户完成“添加订阅 → 启用并连接/稍后”，分流方案可在订阅详情单独选择；必要校验在内部完成，以后更新重新应用覆写。交互与草稿/已发布反馈见[界面契约](ui-workflows.md)，不要求先配模板或手改大量 YAML。

跨平台兼容以策略语义为准：区域组、服务组依赖、规则优先级、必要节点及幂等性。`smart`、`url-test` 与 LightGBM 启用状态分别表达，不静默改变选点行为。网关 NAS/设备规则与桌面 DNS 不自动继承到手机。

个人 Canonical v3 策略作为外部私有输入；公开代码只定义通用接口和合成测试。精确行为须用获授权的策略或脱敏夹具验证，历史 Android 模板不能自动成为权威策略。

### Smart 地区策略

首次导入中，若原文与启用的 Merge 均无 `smart`、`url-test`、`load-balance` 策略组，且所选 `select` 组含直接列出的节点或已校验的 provider 节点，可预览按名称猜测的地区、未知节点和数量。用户可以逐个修正猜测；猜测并不证明节点的实际地理位置。`use` 与 `include-all` 只读取应用私有目录中已校验的 provider 快照，不请求远端 URL；快照缺失时显示待解析，不把尚未加载的节点当作空集。`filter` 与 `exclude-filter` 仅筛 provider 节点，直接列出的节点先行分类。嵌套策略组、relay、dialer 引用不会被展开为普通节点。

“按地区”只生成有节点的 Smart 组与一个新地区入口；“全部节点”要求至少两个已验证节点。新入口加入用户指定的原 Selector 作为一个选项，新入口只指向生成的 Smart 组，不回指原 Selector。原规则的顺序、条件和目标均不变。生成的 Smart 组设置 `empty-fallback: REJECT`，避免动态空组落到直连。“仅创建”保留当前手动选项；“创建并启用”记录用户明确的选取意图，在 Controller 就绪后只选择一次新增入口，之后的手动选择不被订阅更新覆盖。关闭时移除生成入口并尝试恢复启用前的选项；若原选项已失效则先要求用户手动选取可用节点。策略计划保存在该订阅的不可变版本来源记录中；关闭、重新启用及订阅更新都经同一配置事务重新生成并校验，原订阅文本保持不变。

## 验收

覆盖完整 YAML 与 provider；保留节点；无重复组/规则、无悬空引用；缺必要节点明确失败；保持规则优先级；重复转换幂等；更新重新应用覆写；启动/重载平台字段一致；生成、保存和内核应用失败均可回退。合成测试与云端构建验证事务结构；真机上仍需核对启动和热重载实际生效、停止确认及网络转发。

## 版本回收与读者

成功发布或删除订阅后，现有事务门禁保持持有并在同一 worker 调用 GC。可达集合为 Current、Previous、全部 Profiles 及备份/回滚的额外 pins。编辑意图的 sourceRevision、draft revision 和字段指纹不是版本引用；原文/覆写文本草稿也不增加版本引用。

Stage 的 `.pending` 只在成功 Publish 后移除。未提交候选、应用 unknown、备份恢复 journal、损坏/未知状态 schema、额外文件和任意 symlink 都使清理拒绝，不推测引用。GC 先完整验证目录与 provenance，再把不可达版本隔离为 `.gc-version-*`，删除来源记录最后完成；中断后只续清已验证隔离目录，未知文件不删除。状态指针在清理前后保持不变。GC 错误不能把已经提交的配置变成假失败。

Go 异步读者须用 `FileStore.AcquireReadLease` 覆盖读取生命周期；读者、stage/publish/discard 和 GC 使用同一个跨进程文件锁。ArkTS 同步读取在一次门禁/调用内完成；不能在 await 后沿用旧 Version 对象，异步页面须重新核对 ticket。备份/回滚持久引用须显式传入 pins 或持有恢复 journal，不能仅保存在页面变量。

`EffectiveVersions.storageReport` 供高级存储详情按需读取 `gc-status.json` 的容量、回收数量和固定错误码；complete=false 表示本次计量不完整，缺失报告不等于零用量。默认界面不要求用户管理版本文件。

## 设置保存与连接快照

普通设置使用 `Settings.save(context, settings, fields)`，只提交明确修改的字段；同进程所有偏好写入（包括 Smart 与 LAN 独立授权）串行等待异步 flush，确认完成后才反馈成功。等待中的 Preferences cache 不作为已保存值。失败恢复缓存，跨页进入先等待队列并读回已确认快照。LAN 撤销/授权仍有独立确认及失败保护，未确认的授权写入拒绝新连接。

每次启动的系统配置和 `HOST_SETTINGS` 来自同一份主进程已确认快照；VPN Extension 不跨进程重用 Preferences 缓存。启动后的偏好修改留到后续连接，设置中的“重连应用”须确认中断，取消、切页或旧会话确认不能重启新连接。

配置事务持有 Controller 发布门禁以阻止新连接越过在途操作，停止仍可立即取消旧代次。apply、commit 与 rollback 的完成边界重新核对会话及操作身份；HTTP payload 携带 expectedSession，服务端在应用前核对，旧回滚不能作用于新内核。已发布后才发现会话变化时保留真实指针并进入 unknown，不报告 applied 或盲目覆盖新会话。 Smart 偏好与版本发布结果共同对账：仅确认未发布且旧指针未变时恢复旧偏好；已发布或发布结果无法确认时保留候选偏好，不将控制面 unknown 当作未提交。重命名前先检查全部目标侧车、草稿与元数据，拒绝碰撞后不得移动或覆盖任一来源资料。

完整来源上限 15 MiB，生成 YAML 上限 16 MiB。Controller JSON 传输限额独立计入包装和最坏转义，解码后仍严格限制 YAML 字节；worker 请求亦有独立有界传输限制，不静默截断。文件导入读取用 BoundedFileReader，写入用 `ProfileStore.importContentAsync` 的有界异步短写循环及原子移动。

## 本地备份恢复

设置页的本地备份由用户主动导出并用系统 picker 选择位置；操作前短提示订阅地址/节点凭据风险。schemaVersion=1 的清单仅含原始来源、启用的全局/本订阅 Merge、地区/EditIntent（含模板/Smart 例外）和明确列出的普通偏好；不含 LAN 授权、Controller secret、日志、签名或运行时会话。不自动上传。单文件最多 64 MiB、128 个订阅；来源仍遵守 15 MiB，候选仍遵守 16 MiB。未知版本、损坏、路径穿越、重复名称和无法完整校验的候选拒绝。

`LocalBackup.preview` 异步读取用户选择的文件，通过原有 compiler/FileStore stage 全部候选；同名内容另存为唯一名字，预览后确认设置/全局覆写变化以及运行中断。确认后 `LocalBackup.restore` 先复用 Controller 的确认停止，再持有 ProfileTransactions 同一门禁，一次 Publish 全部目标引用，保留当时 Current 为 Previous。不会按条导入并假报整批成功。

Preferences 写队列在恢复期间持有 `backup-restore.json` journal：先记录旧/新完整可移植偏好与前后版本快照，再写偏好、发布目标，最后按真实指针对账并 durable flush。丢失响应由同一 worker 的 status 核对；重启时 Settings 在启动/普通写入通过 idle 前，从 journal 和实际 state 选择旧/新偏好。无法确认时保留 journal 并拒绝新启动。LAN 授权与运行连接标志始终来自本机，不从备份迁移。

未发布候选有 `.pending`，journal 存在时 GC 拒绝；导入取消清理候选，冷进程首次加载会清理遗留预览及应用私有传输文件，真实 Current/Previous/Profiles 引用不会被删。Go 读取持有相同读者租约。正常完成后复用版本 GC；清理失败不否认已发布配置。系统 picker 写入失败可能留下未完成的目标文件，界面不报告已保存；应用私有临时文件在 finally 清理，系统文件位置由用户管理。

备份预览绑定 config/original/source/可选 overlay 的精确字节摘要，在 arm 与 commit 均复核，合法 YAML 内容变化也须重新预览。arm 回复丢失即封锁普通设置写入，在同一 worker 顺序确认恢复 journal；无法确认则保留恢复锁，不能让冷恢复覆盖后来保存。prior/target 相同的空备份用持久 committed 位区分完成阶段。运行态手动地区选择和观察值不导出，恢复只从已启用计划建立新的 pending。系统 picker 的迟到返回仅能释放自己的操作门禁。
