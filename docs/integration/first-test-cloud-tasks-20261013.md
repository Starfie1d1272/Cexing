# 首轮设备验收后的独立修复任务

输入为 [2026-10-13 真机报告](../evidence/first-test/2026-10-13-device/README.md)，源码基线 `8773a79c573cec2bc7a2f83ad6fa4ff103462a51`。每项独立提交/审查，保留正式包名、ProfileStore 数据和四 C ABI。云端使用合成数据与本地可控节点；设备复验仍由本地完成。

## 1. P0：定位真实转发失败并补齐有界错误证据

症状：手机域名/IP HTTPS 页面无响应；辅助 mixed 请求 HTTPS 握手失败、HTTP 502；启动状态为 Connected，现有诊断只报告就绪。根因尚未证明。

先检查 `core/engine.go`、`core/platform_ohos.go`、NAPI worker 和 VPN 扩展的进程网络保护边界、DNS 与连接错误传播。用两个可控本地代理和 HTTP/TLS 目标验证配置流水线、代理链、写入/读取及失败恢复。区分可用节点、解析、上游握手和 OHOS socket；取得复现证据后只修对应根因。

失败摘要只记录阶段、脱敏错误类别、系统 errno/状态和构建身份，禁止保存私有 URL、域名/节点凭据、Controller Secret 或请求载荷。启动成功与真实请求成功分别呈现。

完成条件：云端受控连接回归及错误传播通过；本地在已确认可用节点上取得浏览器成功响应、实际代理链和双向字节，再关闭/重连复验。云端通过不能代替该设备条件。

## 2. P2：点击断开直接执行

`HomePage.ets` 的 Connected 分支当前打开 AlertDialog。用户要求单击直接断开。

移除该确认步骤，继续调用 AppRuntime 主动取消恢复及 VpnController 的现有停止路径。连接中取消、断开中的禁用和旧回调不能停止新会话等保护保持成立。

完成条件：单击停止，停止完成后回到未连接；无二次确认；快速启动/取消/重新连接不被旧任务影响。

## 3. P2：已连接时完整显示面板入口

当前默认竖屏连接后，速率区使工具列超出 Scroll 可见高度，Zashboard 标签仅余 26 px；向上滚动可恢复。定位 `HomePage.ets` 的连接卡、工具区、滚动区域与底部固定按钮，以及 Index 的悬浮页签内容留白。

用最小布局调整保证默认已连接视图的面板入口完整可见、可点，底部断开按钮与页签安全区分开。保留原有页面结构与滚动能力。

完成条件：同机未连接/连接中/已连接、短高度和大字号截图；面板入口无需猜测滚动位置，主动作不截断或覆盖其他交互。

## 4. P2：诊断使用用户语言，并改善入口样式

当前文案包含“系统会话、内核、控制面、Controller、宿主报告”，首页入口是透明短按钮。将默认界面改为清楚的连接状态和用户能执行的检查；技术详情可按需展开。检查尚未运行或仅验证本地服务时，仍准确表达范围。

首页入口采用与现有工具入口一致的明确点击样式、足够触区和无障碍标签。只调整 Home/Diagnostics 所属范围，复用现有状态、检查和失效回调保护。

完成条件：用户能识别入口与检查结果；不将本地服务可达写作“网络正常”；原生实测点击检查能完成或给出有界失败提示。

## 5. P2：订阅命名的文件名回退

`ProfileName.ets` 已支持 Content-Disposition 的普通及 UTF-8 扩展文件名；`ProfileStore.importFromUrl()` 在缺少该头时直接传入 `sub_时间戳`。本轮 `profile.yaml` 路径没有参与命名。

优先保留响应文件名，其次使用 URL 中合法的 YAML 文件名；无法提取时使用易读默认名称。不要把订阅 token、查询参数或不透明路径当成显示名称。保留现有手动名称和原文件；新增导入不得覆盖同名已有配置。

完成条件：响应头、中文/编码路径、无文件名 URL、畸形编码、路径穿越、重复名字及用户重命名回归通过；手机无响应头文件 URL 显示正确名称，已有数据保持。

## 后续构建维护项

面板 `dependency-notices.json` 目前由当前平台安装出来的可选依赖目录决定，Mac/Linux 会得到不同资源锁。独立修复 `scripts/zashboard-assets.py` 的可复现许可清单生成：锁定完整且明确的依赖集合，保留许可证文本及完整性检查，在两平台核对同一资源身份。SDK 实际组合与固定 CI pin 分开记录，不能移除检查来接受不匹配。

另保留低优先级回归项：ProfileStore 删除应完成异步 unlink 后再报告成功/刷新列表，并实际验证失败传播。首轮只在清理测试副本时观察到一次列表短暂残留。

首轮阻塞修复并在设备复验通过后，再制定 DNS、IPv6、后台保活、网络切换和 LightGBM 预测的第二轮清单。
