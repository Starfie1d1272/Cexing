## 第一批任务

1. **P0-01：完成签名与原始设备基线。** 用户提供 AGC cer/p7b；核对包名、设备/profile与证书。安装前确认覆盖风险；导入订阅与VPN授权后采集真实出口、日志、进程和回环端点证据。
2. **C-01：统一安全配置应用 contract。** owner 为 core/engine、platform_ohos、CoreApi、VpnController和订阅更新入口。强制回环、随机secret、HTTP/WS认证、热重载保持平台约束。先定义字段与生命周期再改代码。
3. **P1-01：固定最新 Smart 候选并实现模型闸门。** 保留ABI，复用已试编译recipe；取得模型授权，校验摘要/解析/原子铺盘，诊断区分模型与Smart选路状态。
4. **P2-01：最新 Zashboard 正式版静态资源试构建。** 固定release/lockfile、验证完整dist和本地字体，设计资源清单及入包检查；这一工作可在P0签名等待时独立进行。
5. **P4-01：真机稳定性矩阵与双栈缺口。** P0后先测现有dataTransfer实况窗，再决定ACL方案；核对IPv6地址和恢复状态，不先叠加保活策略。

## 后续任务拆分

P0 未验收前允许独立研究和隔离试验。P0 后，Smart 模型与 Web 资源模块可以并行开发；C-01 为共享依赖，应有单一 owner 避免重复写 secret、端口或重载逻辑。P4 矩阵可以同步制定并持续回归。P3 等待 P1/P2 contract 和生命周期 owner 明确后开始。

后续提交按文档、安全contract、Smart、资源/ArkWeb、原生流程等语义单元组织。每次内核/资源改变均 clean HAP，验证包内实际身份；签名凭据、订阅、HAP、libs与工具链保持忽略。
