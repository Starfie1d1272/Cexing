# 视觉规范

采用 `ark + minimal`，保留三页签与原生顺序。阅读层级为状态 → 主动作 → 当前配置 → 面板；首屏不列节点和日志。大号状态字、细分区线、方形状态点与轻微圆角形成识别，避免装饰 HUD、随机数、扫描线和持续动效。

## 布局与操作

基准视口 390×844，额外检查 360×800、412×915。CSS px 仅用于原型视口；ArkTS 实施用 vp/fp 与实际设备窗口宽度，不把物理像素直接当 vp。水平边距 20、卡片内边距 14、区块间距 12–16，状态卡主按钮离正文 12；按钮圆角 4。主要触区高 ≥48，导航高 ≥60（含容器间距），单行表单高 50；保留全宽主动作。演示选项也使用 48 高触区。状态栏与底部手势条为浏览器样机表现，生产页不得重复绘制系统状态栏。

主体滚动、顶部与底部固定；窄屏文本换行、无横滚。导入/预览允许滚动，不为了首屏展示缩小字。安全区域在 CSS 使用 env 回退；浏览器无法证明 HarmonyOS 的实际安全区域，实施需窗口 API 和真机验证。较大字号必须在 ArkTS 检查卡片增高、按钮换行、底栏可读，不写死状态卡高度。

键盘操作使用原生 button/select/input，提供可见焦点，页签 aria-current，恢复与更新开关使用 role=switch/aria-checked，连接副文案带 status。没有持续动画；遵循减少动态效果偏好。状态变化若加入过渡仅建议 120–180ms，减少动态效果时取消。上线需验证屏幕阅读器通知、焦点返回与中文字体放大，浏览器演示不等于原生无障碍验收。

## minimal 与 moderate 对照

内容、交互、触区与状态完全一致。minimal 只调整字体、颜色、边线和关键状态。moderate 增加状态卡一条竖导轨、一处静态斜切和较强页首分割；几何位于文字外，不参与点击裁剪。两档均没有无意义仪表与动画。建议 minimal 作为生产实施起点，moderate 用于视觉评审，不增加额外业务复杂度。深浅色分别截图见 [总览](overview.html)。
