## 逐页结论

| 页面 | 结论与理由 |
| --- | --- |
| 已选连接首页、未连接、系统授权示意、断开确认 | 保持：白色状态场、斜切块面、黑色数据带与三页签已获得认可；工具页不复制斜面 |
| 订阅列表／添加订阅菜单 | 保持：主标题600、列表标题550形成角色层次，线性文件／链接图标同源，主次文字与留白一致 |
| 设置默认／网络／内核设置 | 保持分组、开关、文本和保存层次；仅开启自动更新后修间隔选择器 |
| 设置／自动更新间隔 | 调整：原选择器11px、bottom margin14px导致偏小偏上；改14px、48px触区、垂直居中与现有表单边框色。选择行为不变 |
| 订阅详情／删除确认 | 调整：删除入口文字及确认按钮用既有错误语义红棕色 #923f2e，避免与更新／保存等普通操作混同；确认文案和行为不改 |
| 链接／文件／剪贴板导入、导入失败、确认启用 | 保持：输入与主动作清楚，红棕错误提示已有独立层次，输入数据与异常恢复不删减 |
| 覆写选择／Merge编辑／差异预览 | 保持：选择、编辑、比较层次各自承担任务，等宽文本仅用于YAML；保留方案预览信息，不能视觉上暗示生产合并已经完成 |
| 重命名、按应用分流选择 | 保持：底部弹层与表单具有明确标签和返回动作，图标与触区一致 |
| 诊断 | 保持：四层事实与分享／日志入口各有所有者，不合并系统会话、内核就绪与转发健康 |
| Zashboard 接入占位／失败 | 保持：明确交接和错误恢复，没有另一套节点管理；尚未接入真实面板，不能为视觉统一抹去事实 |

## 视觉与交互依据

沿用已安装 Ark Skill 固定版本的方法：每个数据一个所有者，极简允许功能性错误色，字体权重按角色区分，工具页保留原生习惯，不把首页构图变成每页装饰。600标题／550列表／400输入的不同是有意层次，原青色信号与可读深青操作色承担不同角色，无需机械统一为一种明度。没有新增图标、字串、遥测或动画。

主卡实现直接引用 `connection-planes/home.js` 和 `home.css`；CSS只有settings的#interval和profile的delete/deleteConfirm选择器，首页、页签与普通按钮不匹配。固定首页三个运行文件已与Git0974f9d逐字节核对。

实际看过14页原稿联系图以及修整后的间隔、删除入口、删除确认前后实图。26个页面/状态×390×844与960×720：52组状态与可见文本相同；46组逐像素完全一致，6组变化仅发生在三项调整状态（每项两个窗口）。验证器对未改区域允许最大1级原生圆角抗锯齿误差，本次最终结果未使用该容差，未改状态最大差值为0。设置和删除截图采用固定scrollY=200以展示控件，前后相同；宽屏改变控件的原始PNG见screenshots/before和after。

交互检查：间隔24→48小时正常，触区至少48px；跨页保持合成连接；删除确认背景inert，关闭保留订阅，确认才删除内存配置；已选首页断开路径通过。无浏览器异常或横向溢出。

复现：仓库根启动 `python3 -m http.server 8765`，执行 `python3 design/native-ui-fresh/page-consistency/verify.py`。需要 Python Playwright/Pillow 与 Chromium。测试只是浏览器原型证据；未改ArkTS生产源码，未重跑HAP／设备功能验证。

## 实施边界

间隔选择器在原生迁移时采用平台原生选择控件；破坏性动作使用项目错误语义色并保留显式确认。页面只展示AppRuntime状态，不持有VPN生命周期。系统授权继续由OS承担，订阅事务与Zashboard认证接点完成后再连接真实数据。技术线进展、尚未接入项与验收缺口见IMPLEMENTATION-GAP.md。
